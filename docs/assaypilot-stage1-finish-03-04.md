현재 AssayPilot 저장소에서 1단계 마무리 작업 중 ‘3. 실제 원본·설정·산출물·로그 보존 및 오프라인 재현’과 ‘4. AID별 endpoint·판정 의미와 공개 근거 검토’를 수행해라. 필요한 구현 수정과 실제 검증까지 끝내고, 이번 묶음에서 종료한다. 다음 묶음이나 2단계를 자동으로 시작하지 않는다.

**작업 문맥과 선행 결과 확인**

0단계 계약과 1단계 데이터 계층이 구현되어 있다. 앞 작업에서 입체정보를 보존하는 SMILES 수집 정책과 실제 RDKit 감사가 보완되었다는 전제로 시작하되, 실제 코드와 결과 보고서로 상태를 확인한다.

- AGENTS.md, git 상태, 최신 domain/data 코드, README와 stage1 문서, 실제 캠페인 설정, reports/stage1_completion/01_structure_audit.md를 읽는다. 보고서 위치가 다르면 현재 저장소에서 찾는다.
- 앞 작업의 SMILES 선택 정책과 실제 감사 결과를 유지한다. 선행 검증이 막혔다면 그 사실을 넘겨받고, 진행 가능한 보존·의미 검토는 수행하되 최종 완료를 허위로 표시하지 않는다.
- 기존 MEP2 설정은 primary AID 2016, confirmatory AID 2272이며 관계 근거로 AID 504468이 제시되었다. 이전 raw cache와 bundle 경로는 /tmp/assaypilot-real.zzD33F/였지만, 이 경로의 존재나 내용이 유지되어 있다고 가정하지 않는다.
- 최신 코드·설정·원본을 기준으로 판단한다. 기존 사용자 변경, 0단계 Protocol, 공개/미공개 분리, 초기 as_of 의미를 보존한다.

**3. 재현 가능한 실제 snapshot 보존**

프로젝트에 데이터 보관 관례가 있으면 따른다. 없다면 data_snapshots/<campaign_id>/<snapshot_id>/처럼 /tmp 밖의 명시적인 프로젝트 데이터 경로를 사용한다. 별도 외부 저장소 구축이나 클라우드 배포는 필요하지 않다.

다음 자료를 묶어서 보존한다.

| 자료 | 보존할 내용 |
|---|---|
| 설정 | 실제 사용한 설정 원문, 후보 선정·seed·초기 시각·구조 정책 |
| 원본 | 실제 응답 바이트, 요청 정보, 수집 시각, 형식, SHA-256 |
| 산출물 | public/와 curator/ 전체, 각각의 기존 manifest와 provenance |
| 검증 | 실제 build·Adapter·Auditor·inspect 결과와 감사 범위 |
| 구현 식별 | 코드 커밋, 미커밋 변경 여부와 재현에 필요한 변경 소스 식별, Python·주요 의존성 버전 |

- 이전 입력이 남아 있으면 먼저 보존한다. 파일이 사라졌다면 정확한 과거 snapshot의 보존은 불가능했다고 기록하고, 새로 수집한 자료를 별도 snapshot으로 취급한다. 과거 보고서의 행 수를 맞추려고 데이터를 수정하지 않는다.
- snapshot 전체를 식별하는 설정·파일 해시 목록을 개발자용 위치에 둔다. 런타임 public/manifest.json에 curator 해시·경로·통계를 추가하지 않는다. 공개 bundle의 ID나 내용 해시에 원본 전체 또는 미공개 정답의 해시를 섞지 않는다.
- 큰 원본과 개발자용 자료를 무심코 Git에 추가하지 않는다. 설정·재현 명령·작은 fixture·코드·문서는 프로젝트 관례에 맞춰 관리한다. 자료를 보관한다는 것과 에이전트에게 공개한다는 것을 구분한다.
- 수정 전 snapshot을 보존하고, 의미 매핑 수정으로 결과가 달라지면 새 revision을 생성한다. 기존 snapshot의 파일을 바꾸면서 이전 해시·실행 기록을 유지하지 않는다.
- 저장은 기존 수집·build 모듈을 호출하는 간단한 스크립트나 명령으로 재현되게 한다. 별도의 데이터 파이프라인을 복제하지 않는다.

오프라인 재현은 다음 방식으로 한 번 끝까지 확인한다.

1. 고정된 설정과 보존한 원본 캐시만 사용하여 새 출력 디렉터리에 build한다. 이 경로는 네트워크를 호출하지 않아야 한다.
2. 기준 산출물과 공개 파일의 내용·상대 경로·해시를 비교한다. 개발자용 실행 시각처럼 달라질 수 있는 메타데이터는 구분하되, 공개 데이터 차이를 숨기기 위한 임의 정규화는 하지 않는다.
3. public/만 복사한 디렉터리에서 실제 RDKit이 있는 환경으로 Adapter → Auditor → inspect를 실행한다.
4. 이전 성공 산출물을 덮어쓰지 않고 입력·결과·명령과 비교 결과를 남긴다.

**4. 실제 시험의 의미와 매핑 확인**

공식 assay description, protocol, 결과 정의와 실제 결과 행을 대조한다. 원본 캐시에 필요한 공식 설명이 있으면 재사용하고, 없다면 명시적인 수집 경로로 확보한다. 공식 설명을 확인하지 못했으면 미확인으로 남긴다.

검토 대상은 실제 사용하는 AID 2016과 2272, 두 시험의 관계 근거인 AID 504468이다. 각 AID의 실제 역할을 원문에서 확인하고, 관련 AID의 숫자나 이름만으로 관계·역할을 추정하지 않는다. AID 504468을 관계 근거로 사용한다는 이유로 실행 시험에 추가하지 않는다.

각 시험에 대해 다음 대응표를 작성한다.

- 실제 생물학적 시스템과 측정 readout.
- primary/confirmatory 등의 역할과 근거 위치.
- raw Activity Outcome별 의미와 내부 verdict 대응.
- Activity Name 및 선택한 endpoint의 의미.
- 수치 열, 단위, 비교 연산자, 결측·범주 판정만 있는 행의 처리.
- 성공 조건과 선행조건의 해석.
- 원문 URL·기록 식별자·인용 위치 및 확인에 사용한 원본 파일 해시.

다음 해석 오류를 방지해라.

- Activity Value [uM]라는 열 이름만 보고 IC50, EC50 또는 결합 친화도라고 정하지 않는다. Activity Name과 실제 시험 정의를 확인한다.
- 한 assay에서 서로 다른 Activity Name이 존재하면 이를 같은 endpoint로 조용히 합치지 않는다. 설정상 지원 범위를 명시하고, 지원하지 않는 의미는 진단한다.
- MEP2/TOR GFP readout의 활성을 MEP2 직접 결합이나 치료 효능으로 바꾸어 서술하지 않는다. 실제 측정과 가설을 구분한다.
- concise CSV에 primary 수치 readout이나 세부 조건이 없다면 그 한계를 기록한다. 현재 범주 판정만 지원하는 것이 타당하면 verdict-only 범위를 명시한다. 수치를 만들어 채우지 않는다.
- 필요한 의미를 현재 형식으로 표현할 수 없다면 실제 필요한 한정된 매핑·파서 보완을 수행한다. 모든 PubChem 형식을 처리하는 범용 엔진을 새로 만들지는 않는다.
- identity 단위 정책은 원본과 출력의 의미·단위가 실제로 같은 경우에만 유지한다. 일치하지 않으면 값을 조용히 통과시키지 않는다. 범용 단위 환산기 구현은 요구하지 않는다.

실제 자료에 존재하는 판정·수치·결측 유형을 대표하는 소수의 행을 원문과 대조한다. 없는 유형은 ‘원본에서 확인되지 않음’으로 기록한다. 검토용 행을 고르는 것은 개발자용 감사이며, 이를 이유로 공개 후보군을 바꾸지 않는다.

**공개 근거의 내용 검토**

- public/evidence의 내용과 EvidenceRef.location을 실제로 확인한다. 초기 공개 관측과 허용된 시험 방법을 뒷받침하는 최소 내용만 둔다.
- 결과 요약, 성공 후보 목록, 후속 실측값·양성률, 미공개 측정 존재 여부, curator/원본 전체 경로가 섞여 있으면 제거하거나 공개용 사본으로 분리한다.
- 원래의 공식 출처 식별자는 보존한다. 공개용 발췌의 출처와 제외한 범위는 개발자용 provenance에 기록한다.
- 공개 manifest가 실제 공개 근거 파일을 빠짐없이 관리하고, 공개 관측이 존재하는 근거를 참조하는지 확인한다. 해시 검증과 내용의 공개 적합성 검토를 구분한다.
- 공식 URL이 존재한다는 이유로 향후 에이전트의 무제한 원문 재조회가 안전하다고 가정하지 않는다. 실제 도구·파일 접근 제한은 2단계 책임으로 인계한다.

**필요한 수정·검증과 최종 인계**

확인한 불일치만 코드·설정·공개 근거 생성기에 수정한다. 수정한 매핑은 실제 원본의 작은 사례로 회귀 검증한다. 후보군 확장이나 광범위한 경계 테스트 추가는 다음 묶음에서 수행한다.

결과를 reports/stage1_completion/02_snapshot_semantics.md에 작성한다. 다음을 포함해라.

- 실제 snapshot 경로, 기준 설정, 전체 해시 목록의 위치, 실제 재현 명령과 비교 결과.
- 이전 자료의 보존 여부와 새 수집·revision의 관계.
- 실제 AID별 의미 대응표와 확인된 공식 근거, 수정 사항 및 미확인 항목.
- 공개 근거 검토 결과와 실제 실행한 검사.
- 다음 작업이 사용할 최종 snapshot·설정·코드 상태, 남은 데이터 한계.

최종 완료는 ‘고정 원본으로 공개 패키지를 오프라인 재현함’과 ‘사용 중인 시험의 판정·endpoint·공개 근거 의미를 확인함’을 각각 보고한다. 재현 가능성과 생물학적 유효성·모델 성능을 혼동하지 않는다. 불확실한 의미를 임의로 확정하거나 미실행을 성공으로 적지 않는다.

최종 답변에는 변경 파일, 실제 검증 결과, snapshot 및 보고서 경로, 미해결 항목을 적고 종료해라. ReplayOracle, 예산 차감, 학습, 에이전트 실행 루프와 UI는 구현하지 않는다.
