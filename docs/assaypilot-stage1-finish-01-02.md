현재 AssayPilot 저장소에서 1단계 마무리 작업 중 ‘1. 입체정보를 보존하는 SMILES 수집 정책 보완’과 ‘2. 실제 RDKit 화학 감사 완료’를 수행해라. 계획 제시로 끝내지 말고 필요한 코드 수정, 실제 실행, 검증, 결과 보고까지 끝내라. 이번 작업이 끝나면 종료하고 다음 묶음이나 2단계를 자동으로 시작하지 않는다.

**작업 문맥과 먼저 읽을 자료**

AssayPilot은 여러 HTS 캠페인의 후보에 후속 시험을 선택하는 에이전트다. 0단계 계약과 1단계 수집·정규화·공개/개발자용 데이터 분리·Adapter·Auditor가 구현되어 있다. KLF5나 MEP2에 핵심 코드를 종속시키지 않는다.

기존 구현 보고서에는 MEP2 primary AID 2016과 confirmatory AID 2272를 연결하고, primary active에서 seed 20260915로 후보 5개를 선택했다고 기록되어 있다. 구조는 ConnectivitySMILES만 수집했고, conda drug 환경에 RDKit이 없어 실제 화학 감사는 실행되지 않았다. 이는 이전 상태에 대한 보고이며 현재 코드·환경을 먼저 확인한다.

- AGENTS.md, git 상태, pyproject.toml, domain 계약, data의 schemas/pubchem/normalize/build/adapter/audit, 실제 캠페인 설정, 관련 테스트와 stage1 구현 문서를 읽어라. 파일 위치가 달라졌으면 현재 저장소에서 찾는다.
- CampaignAdapter.load(DataSource) → PublicCampaign, Auditor.audit(PublicCampaign) → AuditResult 및 수정된 시점·객체 갱신 계약을 유지한다. domain이 data를 import하게 만들지 않는다.
- 기존 사용자 변경을 보존한다. 필요한 코드만 고치고, 이미 충족된 요구사항을 다시 구현하지 않는다. 보고된 테스트 통과 수를 현재 실행 결과로 재사용하지 않는다.

**1. 구조 수집 정책 수정**

ConnectivitySMILES는 연결성 표현이며 입체화학·동위원소 정보를 제외한다. PubChem의 SMILES 속성은 이러한 정보를 포함하는 표현이다. 현재 공식 설명과 실제 응답 필드를 확인한 뒤 수정한다. 참고: https://docs.pubchempy.org/en/latest/api.html#pubchempy.Compound.connectivity_smiles 및 https://pubchem.ncbi.nlm.nih.gov/docs/pug-rest

- 실제 구조 입력에는 PubChem SMILES 속성을 우선 사용한다. 이미 저장된 ConnectivitySMILES의 열 이름만 바꾸거나 RDKit 변환으로 누락된 입체정보를 복원했다고 간주하지 않는다.
- 기존 ConnectivitySMILES 원본은 덮어쓰지 않고 출처와 함께 보존한다. 두 표현을 보관한다면 용도를 구분한다. 새 요청은 캐시 요청 식별 정보·해시와 일치하도록 관리한다.
- 현재 Candidate.original_smiles 의미에 맞춰 실제 가져온 원본 문자열을 보존한다. 정규화한 문자열이 필요하면 별도로 다루고, 원본을 덮어쓰지 않는다. PubChem 표준화 CID 구조를 depositor가 제출한 원래 구조라고 표현하지 않는다.
- 사용한 속성명, 원본 CID, 요청·응답 출처, 구조 선택 정책을 data 계층의 설정 또는 provenance에 기록한다. 이를 위해 domain의 타입을 불필요하게 늘리지 않는다.
- SMILES가 제공되지 않거나 구조가 파싱되지 않으면 명시적인 진단을 남긴다. ConnectivitySMILES로의 fallback이 필요하면 명시적 정책과 경고를 요구하며, 정보 보존 검증을 정상 완료한 것처럼 보고하지 않는다.
- 원본에서 입체배치가 미지정된 원자는 미지정 상태로 보존한다. 임의의 stereoisomer, 동위원소, salt 처리, tautomer 변환을 도입하지 않는다.
- 기존 후보 선정 규칙, seed, SID/CID 연결, 시험·판정·비용 의미를 이 변경 때문에 바꾸지 않는다. 구조 필드 변경에 따른 bundle·해시 변경은 정상적인 새 산출물로 기록한다.
- 새 구조 요청과 최소한의 관련 수집만 수행한다. 기존 원본 캐시를 사용할 수 있으면 재사용한다. 기존 파일이 사라졌다면 같은 과거 snapshot을 복원했다고 주장하지 말고 새로 수집한 자료임을 기록한다.

**2. 실제 RDKit 감사 실행**

- 현재 작업용 Python 환경과 프로젝트의 data/chem 선택 의존성을 확인한다. 기존 환경을 우선 사용하고 공용·전역 환경을 변경하지 않는다. 호환 가능한 RDKit을 프로젝트 환경에 설치하고 실제 버전을 기록한다.
- 실제 PublicCampaignAuditor가 실제 RDKit의 SMILES 파싱·sanitization 경로를 사용하는지 확인한다. 정상 경로를 mock으로 대체한 검증만으로 완료하지 않는다.
- synthetic 예제와 실제 MEP2 bundle에 감사를 실행한다. 선택 후보 수, 구조 존재 수, 실제 검사 수, 성공·실패 수와 이유를 기록한다. 실패 후보를 몰래 제외하여 성공률을 높이지 않는다.
- RDKit 미설치, 검사 미실행, 검사 수행 후 실패, 검사 통과를 구분한다. 기존 AuditResult 의미를 유지하면서 data 계층의 보고서나 CLI 출력에 검사 범위를 명확히 나타낸다.
- 정상적인 실제 bundle의 inspect가 성공하는지 확인한다. 화학 검사를 생략하거나 오류를 warning으로 낮추어 성공 종료하도록 바꾸지 않는다. 실제 구조 오류가 있으면 추적·수정하거나 해결되지 않은 오류로 보고한다.
- 이 감사는 구조 표현의 유효성 검사다. 생물학적 활성, 결합, 안전성, 약물 적합성을 검증한 것으로 표시하지 않는다.

**3. 필요한 검증**

기존 테스트를 먼저 확인하고 다음 위험을 다루는 부족한 검증만 추가한다.

- 입체정보가 명시된 fixture가 수집·정규화 후에도 원본 표현과 해당 정보를 보존한다. 반대 입체배치를 같은 구조 표현으로 조용히 합치지 않는다.
- 동위원소가 명시된 fixture의 정보가 보존된다. 입체정보가 없는 정상 구조도 정상 처리된다.
- 잘못된 SMILES는 실제 RDKit 경로에서 검출된다. RDKit 미설치 경로 테스트는 유지하되 실제 설치 검증과 구분한다.
- 요청 속성이나 요청 경로가 다른 예전 캐시를 새 SMILES 응답으로 잘못 재사용하지 않는다.
- 구조 수집 변경으로 SID/CID 대응, 후보 선정, 판정, 공개/미공개 데이터 분리가 바뀌지 않는다.

변경 영향 범위의 테스트와 필요한 domain 회귀를 실행한다. 실제 bundle은 수정된 수집 정책으로 구성한 뒤 Adapter → Auditor → inspect 경로를 확인한다. 외부 네트워크 실행과 오프라인 테스트 결과를 구분한다.

**4. 산출물과 종료 기준**

결과를 reports/stage1_completion/01_structure_audit.md에 작성해라. 기존 보고서 규칙이 있으면 같은 책임의 경로를 쓰고 최종 답변에 정확히 명시한다. 이전 실행 기록은 현재 결과로 덮어쓰지 않는다.

보고서에는 다음을 포함한다.

- 변경 파일과 실제 수정 이유, 사용한 구조 속성과 원본 보존 방식.
- Python·RDKit 및 관련 의존성 버전, 실제 실행 명령과 결과.
- 실제 후보 수·검사 수·성공/실패 수, 검사하지 못한 범위.
- 수정 전후 입력·산출물의 차이와 새로운 cache/bundle의 실제 경로.
- 다음 작업이 보존·재현에 사용할 설정, 캐시, bundle, 감사 로그 위치.

새 산출물은 프로젝트의 명시적인 데이터 작업 경로에 저장하여 다음 작업에서 찾을 수 있게 한다. 완전한 snapshot 보관·재현 절차는 다음 묶음의 책임이다.

완료 조건은 ‘구조 정보 보존 정책이 코드와 설정에 반영됨’과 ‘실제 RDKit으로 실제 후보를 검사하고 결과를 확인함’이다. 설치나 네트워크가 막히면 가능한 코드·오프라인 검증을 끝내고, 실제 검사 미완료를 명시한다. 미실행을 통과로 처리하지 않는다.

최종 답변에는 변경 내용, 검증 결과, 남은 문제, 결과 보고서와 다음 작업용 산출물 경로를 적어라. 대규모 후보군 확장, ReplayOracle, 예산 처리, 학습·LLM·UI는 구현하지 않는다.
